# Argon 低档长文本实测（2026-11-10）

测试本地 `127.0.0.1:18083/v1/chat/completions`，模型 `gemini-4-argon`（think=1），单路顺序请求、流式输出；没有经过 CC Switch 或 Claude Code。未修改服务代码、配置。4 次均返回 HTTP 200 并正常结束，上游均自报 `4 Argon`，严格模型检查开启。

## 长输入精确召回

输入为带随机编号的合成中文档案，在约 10%、50%、90% 位置插入三个随机核验值，要求逐字提取到 JSON。每档仅一次请求，字符数包含中英文、数字及标点，不能等同 token 数。

| 输入字符数 | UTF-8 字节数 | 正确召回 | 首正文 / 总耗时 |
|---:|---:|---|---|
| 10,202 | 25,466 | 3/3 | 12.81 / 13.88 秒 |
| 50,202 | 125,774 | 2/3 | 21.66 / 24.47 秒 |
| 100,202 | 251,200 | 1/3 | 62.17 / 64.25 秒 |

10,202 字符样本三个核验值均正确；50,202 字符样本开头和中间正确，末尾返回了错误值；100,202 字符样本只有开头正确，中间和末尾为空字符串。

约 5 万字符输入未触发本地转附件阈值；约 10 万字符输入为 251,200 字节，日志确认超过 MaxPromptBytes=128000 后转为 message.txt 附件。代码此处将完整文本上传，并非主动截去末尾。但这些证据不能区分上游截断、附件摄取限制和模型召回错误，不能据此确定模型的硬上下文上限。项目旧注释中的历史容量估计不作为本轮已验证结论。

## 长输出

要求生成 60 节中文运行手册，每节至少 180 个汉字、全文至少 10,000 个汉字，并带指定结束标记。实际输出 21,957 个字符，其中 19,423 个汉字；60 节按顺序完整出现，每节正文最少 260 个汉字，末尾 LONG_OUTPUT_END 完整。首正文 30.016 秒，总耗时 176.454 秒，SSE [DONE] 与 finish_reason=stop 均存在，未观察到传输截断。首次上游尝试 15 秒首输出超时后重试成功。这里只验证长度、章节、结束标记和传输完整性，不代表逐条审查了手册事实或真实生产可用性。

测试脚本最初只识别单独的 SECTION 编号行，误把带章节标题的输出计为 0 节；修正为支持同一标题行的文字后，对原文件离线重验通过，没有额外模型请求。原始初判保留为 results-original.json，复核结果为 results.json。

## 结论与证据

本轮长输出通过，长输入的精确召回在约 5 万和 10 万字符样本失败。不能把 HTTP 200、附件上传成功或正常结束作为全文可用的保证，也不能用一个约 1 万字符通过样本承诺长期可靠容量。没有请求触发 429，结束时无出口冷却，运行配置保持不变。
