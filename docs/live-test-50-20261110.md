# 50 次混合接口测试（2026-11-10）

测试对象：本地 `http://127.0.0.1:18083`，运行源码版本 `13d5f83`。3 路并发，提交间隔至少 2.5 秒，客户端不重试；服务端保留原有重试策略。共发送 50 次生成请求：25 次文本、25 次生图，覆盖 Chat Completions、Responses、Gemini 原生，流式及非流式。未通过远端 New API 实例测试。

## 结果

| 请求模型 | 次数 | 服务端成功 | 服务端耗时 P50 / P95 |
|---|---:|---:|---:|
| gemini-3.6-flash | 15 | 15 | 16.118 / 60.090 秒 |
| gemini-3.1-pro | 10 | 1 | 60.012 / 60.039 秒 |
| gemini-image | 25 | 25 | 19.499 / 33.695 秒 |

服务端请求记录：41 次成功、9 次失败，成功率 82%。这不是完整内容与参数达标率。客户端已校验内容成功 38 次、失败 9 次，另 3 次图片响应未完成客户端校验。22 张图片已实际解码并检查比例（允许 2% 像素舍入误差）。

9 次失败均为 Pro 首输出超时。日志显示每次等待 15 秒、最多尝试 4 次，约 60 秒后失败；其中第 39 次 Responses 流式请求 HTTP 状态为 200，但流内返回错误，按失败计数，服务端请求日志记录 502。Pro 唯一成功请求耗时约 59 秒。不能把 HTTP 200 等同生成成功。

## 图片分辨率

15 次 1K 请求均完成解码与比例检查。5 次 2K 请求中，2 次完成解码，实际为 1696×2528、2304×1856；另外 3 次仅有服务端成功记录。

5 次 4K 参数请求均成功返回可解码图片、比例匹配，但实际尺寸分别为 2048×2048、2752×1536、1536×2752、2400×1792、1792×2400，未达到 4K 分辨率。当前不能向调用方保证该参数会交付 4K 图片。

## 客户端测试限制与修正

前一段脚本使用 `iter_lines(chunk_size=1)`，导致大图片 SSE 数据逐字节解析耗时异常。确认前 40 次请求均已在服务端结束、在途请求为 0 后，终止测试客户端，改为 8192 字节分块读取；随后仅执行第 41–50 次，未重复生成前面的请求。

第 32、36、40 次因此保留为“服务端成功，客户端图片校验未完成”，不能宣称 25 张全部完成文件校验。测试分两段完成，包含客户端解析停顿，总墙钟时间不能直接作为接口吞吐量。上表使用服务端请求记录耗时，包含成功和失败请求。修正后第 44 次 4K 流式图片在约 26.5 秒内完成客户端校验。
